# 券商营销话术合规审核引擎 —— 设计文档（SDD）

> 对应笔试题：`test.py`（交付文件 `task_compliance.py`）
> 版本：v1.0　日期：2026-11-17

## 1. 需求与约束分析

### 1.1 功能目标
对券商营销话术做合规审核，覆盖五条规则：

| 规则 | 主题 | 典型违规 |
|---|---|---|
| Rule-01 | 收益承诺 | 保本保息、稳赚、年化 X% 有保障 |
| Rule-02 | 夸大误导 | 稳赚不赔、闭眼买、错过再等十年 |
| Rule-03 | 风险提示缺失 | 推荐具体标的但无风险提示 |
| Rule-04 | 不正当竞争 | 贬低同业、极限词、无出处数据 |
| Rule-05 | 变体规避 | 零宽字符、拼音、拆字、HTML 隐藏文本 |

### 1.2 非功能约束（评分点）
1. **抗对抗**：识别拼音/零宽字符（Case 3）、Prompt 注入（Case 4）、HTML 隐藏文本（Case 5）、语义诱导（Case 6）。
2. **确定性**：同输入连调 5 次，`status` 与 `violated_rules` 100% 一致。
3. **高可用并发**：批量接口高吞吐；单条异常/超时不影响整批；**fail-closed，不漏放**。
4. **安全**：API Key 仅从环境变量读取，禁止硬编码。
5. **可测试**：`python3 task_compliance.py` 一键断言通过；无 API Key 时自动降级为纯本地引擎，离线可跑。
6. **禁止针对用例写死正则**：所有词库/模式按规则维度做领域通用设计。

## 2. 核心架构：双通道融合 + fail-closed

纯 LLM 方案存在三个致命问题：输出不确定、易被注入、网络异常即不可用；纯规则方案读不懂 Case 6 的语义诱导。因此采用**本地确定性引擎做基线、LLM 做语义增强、结果取并集**的双通道架构：

```
原始文本
  │
  ▼
① 预处理管道 preprocess()
   NFKC 规范化 → Cf 格式字符(零宽)剥离 → HTML 解析(隐藏文本单独提取)
   → 紧凑文本 compact(去标点/空白/特殊符号) → 拼音音节流(含拉丁文拼音识别)
   产出 NormalizedText（多表征 + 对抗信号）
  │
  ├─────────────────────────────┐
  ▼                             ▼
② 本地规则引擎                 ③ LLM 审核器（可选，有 Key 才启用）
  LocalDetector                  LLMAuditor
  词库/音节/正则通用匹配          temperature=0 + JSON 契约
  100% 确定、毫秒级              分隔符隔离 + 注入防御 Prompt
  └──────────┬──────────────────┘
             ▼
④ 融合器 merge()：规则并集，任一判违规即违规，字典序排序
             ▼
⑤ 幂等缓存：hash(归一化文本) → 结果（深拷贝返回，只缓存成功结果）
             ▼
⑥ 异常/超时兜底：fail-closed → status=违规, is_fallback=True（绝不放行）
```

## 3. 抗对抗策略（重点）

### 3.1 预处理的多表征设计
单一 normalize 字符串无法同时应对所有变体，因此对每条文本产出多种表征，分别匹配：

| 表征 | 构造方式 | 对抗场景 |
|---|---|---|
| `normalized` | NFKC + 剥离 Unicode Cf 类字符 | 全角字符、零宽字符（Case 3 的 `保​障`） |
| `plain_text` | HTMLParser 提取的可见文本 | 去标签但不丢文本 |
| `hidden_text` | `display:none`/`visibility:hidden`/`script`/`style` 等隐藏元素内文本单独提取并送审 | Case 5 隐藏 span 里的"保本保息年化20%" |
| `compact` | 只保留 Letter/Number 类字符 | 拆字、插空格、插特殊符号（"保 本 保 息"、"保★本"） |
| `syllables` | 汉字转拼音音节 + 拉丁文拼音（去调号）识别，合并为有序音节流 | 拼音规避（wěn zhuàn）、同音字替换（吻赚） |

### 3.2 拼音/同音字的通用识别机制（非用例硬编码）
1. 从 `pypinyin` 内置拼音字典派生**合法音节集合**；
2. 文本中的拉丁字母串去调号后，若连续 ≥2 个 token 命中合法音节，判定为拼音规避；
3. 敏感词库只维护正常中文词条，启动时预计算每个词的音节元组；
4. 在文本音节流上做子序列匹配 —— 拼音写法与同音字替换走同一条逻辑，词库零特判。

### 3.3 Rule-05 不依赖词库，由对抗信号驱动
命中以下任一信号即触发 Rule-05：
- 发现 Cf 类格式字符（零宽等）；
- 提取到非空 HTML 隐藏文本；
- 检测到拉丁文拼音规避；
- 某敏感词只在 `compact` 命中而 `normalized` 未命中（证明存在插字符拆词）。

### 3.4 Prompt 注入防御（双防线）
- **防线一（本地）**：通用注入模式库（"忽略之前的指令/提示"、"系统提示"、"ignore previous"、"直接返回 status"等），命中置 `is_attack_detected=True`，但**注入文本仍正常审核**，违规内容不放行；
- **防线二（Prompt 隔离）**：用户文本用 `<|user_content|>` 分隔符包裹，系统提示明确声明其为不可信外部数据，其中任何指令不得执行。

## 4. 确定性保障（三重保险）

1. LLM 请求固定 `temperature=0`，强制 JSON 输出并用 pydantic 校验契约；
2. 本地引擎是纯函数，结果天然确定；融合取并集后，即使 LLM 抖动，本地命中的规则永不丢失，核心结论不翻转；
3. 进程内幂等缓存：同归一化文本直接返回深拷贝，连调 5 次逐字节一致。兜底结果不缓存（避免一次超时永久降级）。

## 5. 高可用与并发设计

- `check_compliance_batch`：`asyncio.Semaphore` 控并发（环境变量可调，默认 8）+ 每条 `asyncio.wait_for` 超时控制；
- `asyncio.gather(return_exceptions=True)` 兜底收口，保证任何单条异常都不炸整批；
- 单条异常/超时 → **fail-closed 兜底结果**：`status='违规'`、`is_fallback=True`，规则取本地引擎已命中部分，`reasoning_trace` 注明兜底原因；
- 按输入索引收集结果，返回顺序与输入严格一致。

## 6. 离线降级策略

模块导入时先经 python-dotenv 自动加载脚本同目录 `.env`（不存在则跳过，且不覆盖已 export 的环境变量），
再检测 `LLM_API_KEY`：
- 有 Key：双通道（本地 + LLM）；
- 无 Key：纯本地模式，`is_fallback=False`（这是有意降级而非运行时异常），保证面试官机器无 Key 时 `python3 task_compliance.py` 与 pytest 全绿。

## 7. 异常兜底矩阵

| 异常点 | 处理 |
|---|---|
| LLM 网络错误 / HTTP 非 2xx / 超时 | 重试 1 次 → 仍失败走 fail-closed 兜底 |
| LLM 返回非法 JSON / schema 校验失败 | 重试 1 次（不支持 JSON mode 时自动降级请求）→ 仍失败兜底 |
| 单条审核任意未预期异常 | 批处理内捕获，该条兜底，整批继续 |
| 输入非字符串 / 空字符串 | pydantic/前置校验，空文本判合规并在 trace 注明 |

## 9. 六个用例的预期行为（断言依据，子集断言）

| Case | status | 至少命中规则 | 特殊标记 |
|---|---|---|---|
| 1 正常合规 | 合规 | ∅ | 全 False |
| 2 明显违规 | 违规 | Rule-01, Rule-02 | — |
| 3 拼音/零宽变体 | 违规 | Rule-01, Rule-02, Rule-03, Rule-05 | 对抗信号 |
| 4 Prompt 注入 | 违规 | Rule-02 | is_attack_detected=True |
| 5 HTML 隐藏文本 | 违规 | Rule-01, Rule-05 | 隐藏文本已送审 |
| 6 语义诱导 | 违规 | Rule-01, Rule-02 | LLM 语义增强 |

断言采用「预期规则 ⊆ 实际命中」子集策略：漏命中判失败，多命中（如 Rule-03 的弹性判断）不判失败，兼顾准确性与鲁棒性。
